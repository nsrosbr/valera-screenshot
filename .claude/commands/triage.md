# /triage — роль СТОРОЖ ЛОГІВ

Авторитет процедури — `docs\_MAINTAIN.md` цього проєкту (роль TRIAGE). Стисло:

1. Прочитай `%APPDATA%\<APP>\debug.log` (+ ротацію `debug.log.1`). Нема / чистий → «дій не потрібно»,
   онови `_last_triage.txt`, стоп. `_last_change.txt` не чіпай (ознака незапублікованих правок).
2. Сигнал → дія:
   - `CRASH` → діагностувати виняток (тип/стек із логу; тексту користувача там нема — STD-DIAG-04).
   - `unknown=[...]` → прогалина словника скорочень.
   - `norm=[...]` дивне → калібрування нормалізації.
   - `frame=-` на типовій ситуації → кандидат на нову ситуаційну рамку.
   - `restore` → перевірити відновлення де-іду.
3. Кожен доведений баг → **мінімальний** фікс (консервативність) + іменований регрес-тест +
   гейт `.\test.ps1` зелений (`ALL TESTS PASSED` + `CORPUS >= 95%`).
4. **RELEASE — НЕ тут.** Лише за прямою командою власника (`/release`).
5. Слід у `docs\_MAINTENANCE_LOG.md` — навіть якщо нічого не робив (кредо §16).
