# adapt.md — процедура приведення проєкту до СТАНДАРТУ ВАЛЄРА

> Це **виконуваний плейбук**, не опис. Агент, що потрапив у теку проєкту студії, виконує його
> згори вниз. Джерело правди правил — `.standard\STANDARD.md` (вендорована копія) або
> `D:\Soft\_studio\STANDARD.md` (оригінал). Механічний чекер — `.standard\conform.ps1`.
> Мова відповіді — українська. **ETA — до кожної фази.**

**Один інваріант над усім:** мутувати дозволено **лише у фазі 4 (FIX), лише клас DEV.**
Усе інше — читання, вимір, звіт, ескалація. Порушення цього рядка робить решту стандарту порадою.

---

## Класи враження (вісь усього — STANDARD.md §0.4)

| Клас | Що означає | Дія агента |
|---|---|---|
| **DEV** | не може дійти до встановленого клієнта за конструкцією | **лагоджу сам**, доводжу механічно, дописую журнал. Без ескалації. |
| **FIELD** | може дійти до клієнта | пишу код, **нічого не бампаю**, ганяю гейт, рендерю пруфи, **зупиняюсь із пакетом доказів**. |
| **CROWN** | незворотне й тихе | **відмовляюсь завжди**, пишу причину в журнал, зупиняюсь (§18.1). |

---

## Фаза 0 — DISCOVER *(ETA ~2 хв, нуль записів)*

1. Знайти корінь проєкту (`$PSScriptRoot` вендора піднятий на рівень, або тека з `standard.bind.json`).
2. Прочитати `standard.bind.json` **явним декодером** (STD-ENC-09):
   ```powershell
   $bind = [System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8) | ConvertFrom-Json
   ```
   Нема файлу → проєкт **не прив'язаний**: перейти до §17 крок 6 (вендорити `.standard\`,
   заповнити bind), не адаптувати наосліп.
3. Інвентаризувати дерево проти §2.1 і Додатка E. Відзначити, що є, чого нема — **ще нічого не міняти**.
4. Прочитати `docs\_MAINTENANCE_LOG.md` (останні записи) і `STRUCTURE.md` (реєстр відхилень):
   дізнатися, що вже вирішено, щоб не «лагодити» задеклароване відхилення (§18.1.11).

**Вихід фази:** розумію айдентику, версію піну, наявні відхилення. Нуль мутацій.

---

## Фаза 1 — BIND *(ETA ~3 хв, одна взаємодія з власником)*

1. Перевірити, що всі **вільні** плейсхолдери в `standard.bind.json` заповнені (§0.5):
   `AppId, BrandUk, BrandEn, DisplayName, Repo, ResourceId, MutexHex, ReleaseTitle, Resources, UiLangs`.
2. **Похідні НЕ питати й не зберігати** — вони формула від `AppId` (`Exe`, `AppData`, `EnvPrefix`,
   `Cer`, `UninstallKey`, `Mutex`, `Namespace`). Якщо хтось вписав похідне руками — це запах.
3. Показати власнику таблицю зв'язування. Дочекатися підтвердження, **якщо** щось порожнє/сумнівне.

**Вихід фази:** bind повний і звірений. Нуль мутацій коду.

## Фаза 2 — AUDIT *(ETA ~1 хв)*

```
.\.standard\conform.ps1            # або D:\Soft\_studio\conform.ps1 -Root <корінь>
```

Зібрати всі ненулі. Чекер друкує число, падає ненульовим, **пропускає задекларовані відхилення**
(коли їхній `Check` збігається з реальним ID перевірки). Групи: **[A]** байти/кодування ·
**[B]** секрети/gitignore · **[C]** айдентика · **[D]** цілісність збірки · **[E]** UI/код ·
**[F]** версія/реліз · **[G]** frozen/дрейф · **[H]** док-набір/правда.

Для студійної картини (всі проєкти разом) — `D:\Soft\_studio\fanout.ps1 -WhatIf`:
що змінить ре-синк і де кожен проєкт червоний, **нічого не торкаючись**.

**Вихід фази:** список ненулів із їхніми ID. Нуль мутацій.

## Фаза 3 — REPORT *(ETA ~2 хв)*

Розкласти кожен ненуль за класом враження:

- **DEV** — «лагоджу у фазі 4, ось як».
- **FIELD** — «пишу код, готую пакет доказів (гейт + рендер-пруф), бампу нічого, зупиняюсь на
  затвердженні». Реліз/публікація сюди НЕ входять — це окрема пряма команда (STD-VER-03).
- **CROWN** — «**відмовляюсь**, ось чому»: пін серта, URL/репо, технічна айдентика після релізу,
  сховище сертифікатів, реліз, видалення релізів, мережа/телеметрія, self-grant прав (§18.1).

Якщо ненуль насправді відповідає **задекларованому** відхиленню, чий `Check` ще не зматчився з ID —
це **реконсиляція чекера**, не «прогалина». Записати як таку, не «виправляти» відхилення.

**Вихід фази:** класифікований звіт власнику. Нуль мутацій.

## Фаза 4 — FIX *(єдина мутуюча фаза)*

**Тільки клас DEV.** Кожен фікс — мінімальною зміною (консервативність, §16), із доказом:

- STD-ENC-01/02 — транслітерувати коментарі, рядки з кодпоінтів, `.cmd` → CRLF.
- STD-TREE-02 — вивести `<ROOT>` із розташування, прибрати абсолютний шлях.
- STD-SEC-01 — коментар над патерном `.gitignore`, ніколи в хвості; далі **пробник**
  `git check-ignore -v <secret>` для кожного секрета (STD-SEC-02).
- STD-IDENT-01 — звести айдентику в `src\Ident.cs`, додати у `build_setup.ps1`.
- STD-PIPE-01 — `if ($LASTEXITCODE -ne 0) { throw }` після кожного нативного виклику.
- STD-DOC-03/06/07 — прибрати посилання на неіснуючі файли; шапка == чинна айдентика;
  реєстр відхилень у `STRUCTURE.md` (навіть якщо «відхилень нема»).

**FIELD/CROWN не чіпати** — вони пішли у фазу 3 як звіт/відмова. **Історію журналу не переписувати**
(STD-DOC-05): хибний запис — зберегти, дописати спростування.

**Вихід фази:** дерево полагоджене на клас DEV, кожен фікс доказаний.

## Фаза 5 — PROVE *(ETA ~3 хв)*

```
.\.standard\conform.ps1     # має впасти на менше; кожен лишений ненуль — задеклароване відхилення
.\test.ps1                  # ALL TESTS PASSED + CORPUS >= 95% (STD-GATE-01..03)
```

Візуальна зміна (клас FIELD, якщо була у фазі 3) — рендер-пруф **звіряється оком** власника
(STD-PROOF-01): агент скрін самозасвідчити не може.

**Вихід фази:** число. «Зроблено» = вимірне підтвердження, не «здається».

## Фаза 6 — JOURNAL *(ETA ~2 хв)*

Дописати в `docs\_MAINTENANCE_LOG.md` (**append-only**, STD-DOC-04) запис у форматі:

```
## YYYY-MM-DD (сесія <назва>) <ЗАГОЛОВОК> -> <РЕЗУЛЬТАТ>
ПРИЧИНА:   що і навіщо
ФІКС:      що саме зроблено (лише DEV)
ДОКАЗ:     число гейта / conform / реальний скрін
ГЕЙТ:      ALL TESTS PASSED + CORPUS n/n
ОБМЕЖЕННЯ: FIELD/CROWN, лишені свідомо; що НЕ публіковано
ПЕНДІНГ:   наступні кроки, рішення власника
```

Зміни самого стандарту (не проєкту) — за §22.3: інцидент → пропозиція → **рішення власника** →
правило + правило чекера + тест на правило → бамп `standard.version` → `rebuild.ps1` → `fanout.ps1 -WhatIf`.
